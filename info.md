Stream vs Blog: What's Different? [IMP, DON'T SKIP]
In the stream, we used SageMaker's managed infrastructure. In this blog, we do everything locally. Both work. Here's the difference:
Studio vs Notebook Instance - Studio is a full workspace with multiple apps but needs a Domain setup (which might take some time). A Notebook Instance is a simple Jupyter notebook - no Domain, no hassle. Same code runs on both.
Local Training vs Training Job - Local training runs inside your notebook using its own CPU. The data is already in memory, no S3 upload needed. A Training Job spins up a separate, more powerful machine that pulls data from S3. Use local when data is small. Use Training Jobs when you need big machines or GPUs.
Local Prediction vs Endpoint - Local prediction calls model.predict() instantly in your notebook. An Endpoint is a 24/7 hosted API for production apps - costs $0.12/hour even when idle.
For the ML Challenge: Notebook Instance + local training + local prediction. You submit a CSV, not a running API.

from sklearn.model_selection import train_test_split

# Drop non-predictive columns
df = df.drop("Phone", axis=1)

# Area Code is a code, not a number
df["Area Code"] = df["Area Code"].astype(object)

# Remove redundant charge columns (charges = minutes x rate)
df = df.drop(["Day Charge", "Eve Charge", "Night Charge", "Intl Charge"], axis=1)

# One-hot encode categorical features (Yes/No -> 1/0)
model_data = pd.get_dummies(df)

# Move target to first column (XGBoost convention)
model_data = pd.concat(
    [model_data["Churn?_True."],
     model_data.drop(["Churn?_False.", "Churn?_True."], axis=1)],
    axis=1
)
model_data = model_data.astype(float)

print(f"Processed: {model_data.shape}")
model_data.head()



Key takeaway: Feature engineering often matters more than your choice of algorithm. Spend 70% of your time here.
Feature engineering - this is where data science happens. Let me walk through what each line does. First, I'm dropping Phone number. Why? It's a unique ID - every customer has a different phone number. It doesn't help predict anything. If your data has unique IDs, serial numbers, or row numbers - drop them. They add no value.I moved the target column to position 0, the very first column. Why? Because SageMaker's built-in XGBoost has a rule: give me a CSV file with no column headers, and put the thing you want to predict in the FIRST column. Everything else goes after it. This is the number one beginner mistake. People forget to remove headers, or they leave the target column somewhere in the middle. The model either crashes or trains on the wrong thing. So remember two rules: no headers, target first. Quick aside - someone might be wondering, how do I know these rules? The answer is documentation ;)

# Split into train (67%), validation (22%), test (11%)
train_data, validation_data = train_test_split(model_data, test_size=0.33, random_state=42)
validation_data, test_data = train_test_split(validation_data, test_size=0.33, random_state=42)

# Separate test labels (we'll use these to check accuracy later)
test_target = test_data['Churn?_True.']
test_data_no_target = test_data.drop(['Churn?_True.'], axis=1)

# Separate features and labels for train/validation
train_features = train_data.iloc[:, 1:]
train_labels = train_data.iloc[:, 0]
val_features = validation_data.iloc[:, 1:]
val_labels = validation_data.iloc[:, 0]

print(f"Training:   {train_data.shape[0]} rows")
print(f"Validation: {validation_data.shape[0]} rows")
print(f"Test:       {test_data.shape[0]} rows")



Why three sets? Training data = textbook (model learns from it). Validation = practice tests (model checks progress). Test = final exam (never seen until the end). Golden rule: never touch test data until you're done experimenting.

# Create XGBoost's special data format
dtrain = xgb.DMatrix(train_features, label=train_labels)
dval = xgb.DMatrix(val_features, label=val_labels)

# Hyperparameters
params = {
    "max_depth": 5,
    "eta": 0.2,
    "gamma": 4,
    "min_child_weight": 6,
    "subsample": 0.8,
    "objective": "binary:logistic",
    "eval_metric": "logloss"
}

print("Training locally... (no separate machine needed)")
model = xgb.train(
    params, dtrain, num_boost_round=100,
    evals=[(dtrain, "train"), (dval, "validation")],
    verbose_eval=10
)
print("\nTraining complete!")



This trains right inside your notebook using the open-source XGBoost library. No SageMaker training job, no separate cloud machine, no quotas needed. For the ML Challenge dataset, this is all you need.

for i in range(10):
    pred = predictions[i]
    actual = test_target.iloc[i]
    predicted = "CHURN" if pred > 0.5 else "STAY"
    actual_lbl = "CHURN" if actual == 1.0 else "STAY"
    status = "CORRECT" if predicted == actual_lbl else "WRONG"
    print(f"  Customer {i+1}: {pred:.3f} -> {predicted:5s} (Actual: {actual_lbl:5s}) {status}")




Each prediction is a probability between 0 and 1. Above 0.5 = CHURN, below 0.5 = STAY. The model's confidence matters - 0.92 means very confident, 0.51 means barely sure.
