# Experiment ledger and evaluation contract

Person 1 owns this ledger. Every candidate or matcher experiment that may be
used for a leaderboard upload must identify the exact candidate checksum,
validation checksum, code commit, local score, and decision. Large artifacts
are transferred through Drive; their checksums belong in the corresponding
manifest.

## Frozen evaluation inputs

| Item | Canonical path | Rule |
|---|---|---|
| Master validation IDs | `data/processed/validation_source1_ids.txt` | Never regenerate after experiments begin. |
| Ground truth | Official `dataset/train/train_ground_truth.tsv` | Supplied data only. |
| Local metric | `src/eval/macro_f05.py` | Macro F0.5; report singleton and non-singleton means. |
| Candidate ceiling report | `src/eval/candidate_coverage.py` | Report rank prefixes, caps, country, and truth-cardinality groups. |
| Confirmation split | Generated by `src/eval/prepare_validation_controls.py` | Do not tune thresholds on this subset. |

## Required metrics per candidate version

- Candidate rows and candidate links.
- True-link recall and rows with at least one true candidate.
- Oracle macro F0.5 for top 20/50/100/200/all candidates.
- Oracle results with realistic prediction caps of 3/5/10/all.
- Country breakdown for India and US.
- Truth-cardinality breakdown: singleton, 1–2, 3–5, and 6+ links.
- Candidate and validation SHA-256 values.
